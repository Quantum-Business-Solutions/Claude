How the asset set was identified

How the asset set was identified

Provenance

Source: HubSpot portal 4087538, read through the CMS, Marketing and Automation v4 APIs on 31 August 2026. Every figure on this page was produced by that pass, not carried forward from an earlier version. Two things about how it was read matter, because they are where an audit of this portal goes wrong:

  • Drafts, not published records. All of this work lives in drafts, so the /draft record is the only one that shows it. Reading the base record shows the site as it was before the migration started — which is how an earlier pass concluded that no Praxera page carried a Praxera form.
  • Whole records, not filtered fields. Passing a property filter to the CMS list endpoints silently drops slug and url, which returns an empty result set that looks like a finding.

Classified by address, not by topic. DaVinci sells supplements under its own name to practitioners and runs a private-label business, from one portal, on one contact list, and the phrase “private label” appears on both sides. PetTechLabs, a separate brand in the same portal, runs its own private-label pet line. So nothing was classified by what it is about — it was classified by the address it lives at: the /private-label/ blog group, an info.davincilabs.com/private-label* slug, the pl-demo-* pages.

The first pass matched the string private-label anywhere in an email and returned 394 hits. Requiring an actual <a href> pointing at a private-label URL — rather than the token appearing in an image filename or a CSS class — drops that to 184. Patrick’s June audit, using different instruments eight weeks earlier, found 183. They agree on 179.

Twenty-five posts are about private label but sit in PetTechLabs’ namespace. Topically they qualify; structurally they are another brand’s, and none was moved.

The scripts that produced these counts are in the project repository, so any figure here can be re-run against the portal and checked rather than taken on trust.
