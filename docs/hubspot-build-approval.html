One change from the generated spec — needs your call

The spec sets the key on ea_serial_number for Equipment. The reasoning is sound: a serial is what a technician, a manufacturer and a lease schedule all agree on. But the data doesn't support it. Across 600 equipment records serialNumber has 35 duplicated values and 8 blanks (12345 twice, 20030607-6 twice…), while equipmentNumber is 600/600 distinct with none blank.

Serial as the key kills Equipment sync on the first collision, or silently merges two machines into one record. Recommendation: key on ea_equipment_number, keep serial as an ordinary searchable property.

Equipment already holds this data under other names

The portal's Equipment object has 16 custom properties including equipment_number, serial, contract_number, make, model and install_date. Creating the ea_ versions puts two columns on the same record holding the same value, which disagree the first time either is edited.

Rows where that risk exists are flagged dup below. Decide per row: uncheck to reuse what's there, or approve to create and migrate.
